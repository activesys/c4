# C4 功能测试用例

> 本文件记录 C4 的功能测试用例，每条用例说明：**测试输入**、**测试特性**、**曾经出现的问题**、**修复的版本**。
> 用例对应「曾经暴露的缺陷」，用于缺陷修复后的回归验证。

---

## 用例 1：用户文本描述 ASFP2 接入与转发信息（内容齐全）

- **测试特性**：用户通过一条文本一次性提供全部接入信息——设备与协议、10 个点的「地址:点名」、接收监听端口（9001）、转发目标（127.0.0.1:9900）与转发点表（5000~5009）
- **修复的版本**：C4H1

### 测试输入

```
现在需要接入1号风机的数据，第三方厂家通过asfp2协议给我们转来1#风机数据，10个点，从1000到1009，10个点分别是1000:风速、1001:功率、1002:风向、1003:桨叶角度、1004:发电机转速、1005:齿轮箱油温、1006:塔筒温度、1007:空气温度、1008:空气湿度、1009:大气压强，使用端口9001。我们需要将这些数据转发到II区服务器上，目标地址是127.0.0.1:9900，点表5000~5009。
```

> 关键点：点名、接收端口、转发目标、转发点表全部由用户提供，系统必须**原样采纳**——
> 不得自行编造转发地址、不得改动用户指定的端口，方案摘要须逐条列出「地址 ↔ 点名」映射与接收/转发端口供核对。

### 曾经出现的问题

C4H1 之前：转发点业务字段（addr）未采纳用户提供值，而是被系统自动编造（从 3001 起顺序编址）；
用户指定的接收端口在执行阶段未正确传递（`output_plan_steps` 首次调用因缺 ip/port 校验失败后重试）；
方案摘要不展示端口，用户无法核对。修复后：用户提供的点表、端口、转发点表原样进入 config.json。

## 用例 2：用户未提供点名/点描述

- **测试特性**：用户没有提供点名或点描述
- **修复的版本**：C4H1

### 测试输入

```
现在需要接入1号风机的数据，第三方厂家通过asfp2协议给我们转来1#风机数据，10个点，从1000到1009。我们需要将这些数据转发到II区服务器上，目标地址是127.0.0.1:9900。
```

> 关键点：用户只提供了数据点**地址**（1000~1009），**没有提供点名/点描述**。

### 曾经出现的问题

LLM 在信息收集阶段自行发明了点名「点1000」…「点1009」（中文「点」+ 地址），
最终在执行模块 `merge_config_from_steps` → `handle_add` 的 `point.id` 校验中被拒绝：

```
自动执行失败: point.id "点1000" 包含非法字符，仅允许字母开头
```

根因：`point.id` 必须匹配 `^[a-zA-Z][a-zA-Z0-9_]*$`（字母开头，仅字母/数字/下划线），
而 LLM 发明的点名以中文「点」开头；且 `output_plan_steps` 的运行时强校验未覆盖
`point.id` 命名合法性，导致非法 id 一路漏到 merge 阶段才报错。

## 用例 3：对已接入设备追加数据点，新增点与已有点撞名

- **测试特性**：用户对已接入设备追加数据点，新增点名称与已有点名称冲突（撞名）
- **修复的版本**：（待填）

### 测试输入

前置状态：设备 `hnals_wt1` 已接入，含点 `windspeed`（addr=1000）。

```
给1#风机再追加一个数据点，地址2000
```

> 关键点：新增点的点名（LLM 翻译后）与已有点 `windspeed` 撞名，但 addr（2000）不同，属于另一个点。

### 曾经出现的问题

`handle_add` 的合并分支（`instance.id` 已存在时）按 `point_match_key`（writer 点用 `id`）匹配，
命中后是**覆盖**已有点的业务字段，而非去重。撞名且 addr 不同时，已有点 `windspeed` 的
`addr` 被静默改写成 2000，造成数据损坏且无报错。

期望：撞名时确定性去重（追加序号如 `windspeed_2`），仅当点的业务身份（addr 等）一致时才视为「更新」。
