## 规格地位与断言基准（实现测试代码前必读）

1. **本文件是测试的唯一权威来源**（c4/AGENTS.md 规则 4）：实现测试代码时严格按照本
   文件编写断言，**不得阅读 agent 源码、不得根据 c4 实际输出调整断言**——即使全部
   失败，也说明实现未达成，测试代码是正确的。
2. **断言基准 = 附录 A 的点表基准数据**。全部点数、地址范围、归一化预期均由
   `points/iec104/` 下真实文件直接提取（2026-10-07，SheetJS/python csv 实测），
   与 c4 的任何实现行为无关。归一化规则依据 c4_iec104_client.md §10.2
   `point_normalization`（yx 起点 1、yc 起点 16385、ym 起点 25601；首值 ==起点原样、
   ==0 整段 +起点、==1 整段 +起点−1；首值恰为 4001/6401 且无显式标记时整段按
   16 进制解读）。
3. **前置依赖**：本用例集验收 §2.13 的解析管道（多 sheet 解析、GBK 解码、分块提取、
   fileBlocks、序列重置检测、确定性归一化、excluded 回报、数量对账）。§2.13 实现
   落地前，本文件是**规格锚点**（预期失败的验收标准），不是回归噪声。
4. **真实点表不入库**（位于 c4 仓库之外）：`<工作区根>/points/iec104/`（相对
   `func_case_e2e/` 为 `../../../points/iec104/`）。套件启动时探测该目录，
   **缺失则整组 SKIP**（标注 SKIP-DIR），不得伪造 fixture 替代——本组用例的价值
   就在于真实文件的脏形态。

## RP-01：分文件两表 GBK csv——文件名语境 + 异名分次上传累积

- **测试特性**：① 厂家「分文件分次上传」形态——遥信、遥测各自独立 csv，无任何
  表内类型列；② 类型语境只来自**文件名**（`yxTagTable`/`ycTagTable` 拼音缩写）；
  ③ GBK（GB18030）编码解码（utf-8 强读将乱码）；④ fileBlocks **异名累积**——
  第二次上传不清空第一次的点表，两表合成一个接入草稿；⑤ 万点级规模（12728 点）
  两遍法提取后点数仍精确；⑥ **设备语境列**（表头「设备」列，信号名跨装置重复
  337/4688）→ 裸 id = `设备_点名`，组合重复归零（2026-10-07 实测），验证设备
  语境并入（agent.md §3.2.1.3b）
- **测试输入**：分两次上传 `yxTagTable.csv`（4688 点，地址 1~4688）、
  `ycTagTable.csv`（8040 点，地址 16385~24424），间隔纯文本轮补统一样板必要项；
  第三步**同名再传** `yxTagTable.csv`（内容不变）
- **预期**：
  - 两次上传回执均可见解析结果；第二次上传后草稿点数 = 12728（**不**被重置为 8040）
    【对话】；
  - 类型：csv#1 全部遥信、csv#2 全部遥测，无追问【对话】；
  - 归一化后地址：遥信 1~4688、遥测 16385~24424，**原样无换算**（首值即分区起点）
    【文件】；
  - GBK 解码正确：表头（序号/地址/设备/描述）与中文描述可读，无乱码替换符【对话】；
  - **落盘 id 形态断言**（设备语境并入，2026-10-08 补）：`points[].id` = `设备值_点名归一化`
    形态（「设备」列值 × 描述列点名，跨装置同点名组合唯一）、`points[].name` 保留
    原文点名；首/中/尾各抽 ≥1 点核对【文件】；
  - 同名再传后草稿**重开**、点数仍 12728（yx 块按同内容替换、不叠加重复）——
    验证 §2.13.4 替换语义【对话】；
  - 方案：1 个 iec104 实例 12728 点 + 转发样板生效（1 个 asfp2 实例 12728 点，
    转发地址 10000~22727 顺序编址）；确认执行成功【文件】。

## RP-06：16 进制别名 + Excel 吞址脏数据——正负混合（遥测21）

- **测试特性**：① 「信息体地址」列 4001~411A **无显式 0x/H 标记**、值中含 A~F
  字符——首值恰为 4001 → 整段按 16 进制解读（0x4001=16385）；② **Excel 吞址
  脏数据**：发送编号 223~232 共 10 行（「2_35KV 直流系统」组）的 hex 地址
  0x40E0~0x40E9 被 Excel 存为科学计数法数值（40、400、4000、…、4×10^10，显示
  4.00E+01~4.00E+10）——铁证：前一行 40DF=16607、后一行 40EA，中间恰缺
  0x40E0~0x40E9；文档序在 0x40DF→40 处**严格下降** → 按设计 §2.13.5 确定触发
  序列回落追问（fail-visible），10 行同值亦必撞 L1 重复；③ sheet 名无意义
  （Sheet4），类型语境来自文件名；④ 干扰列三枚（发送编号/网关编号/RTU 号），
  网关编号 7 个值交错但地址连续
- **测试输入**：上传 `遥测21.xls` + 统一样板必要项
- **预期**：
  - **不静默接入、不出可执行方案**：出现序列回落追问，文案可定位（回落位置在
    16607 之后、提及异常行/科学计数法形态之一即可）【对话】；
  - hex 别名识别可见：4001 → 16385 的 16 进制形态判定出现在追问或回执中
    （yc 侧 hex 别名的**正面接入**覆盖由 c4_iec104_client.md §10.6 合成 fixture
    承接——真实样本因吞址转为回落用例）【对话】；

> （c4_modbus_client），转发侧统一样板同 IEC104 组（单 asfp2 实例）。本系列
> 驱动的核心缺口（2026-10-11 现状）：modscan/modbus 地址双轨换算、类型名称
> 同义词映射与地址跨度互证、字序声明解析、多设备展开——L0 hints
> （c4_modbus_client.json `point_field_hints`）目前只有字段语义与交叉规则。

## modbus 域规则（断言口径，2026-10-11 用户裁定）

1. **modscan/modbus 地址双轨**：工业上 Modscan 工具广泛使用，很多厂家把
   modscan 地址（1 基：线圈 00001 起、离散输入 10001 起、输入寄存器 30001 起、
   保持寄存器 40001 起）当作 modbus 地址给出，**实际是错的**——modbus 地址
   0 基（PDU Starting Address）。本系统一律使用 modbus 地址：
   - 点表**两者并存**（如海林表 `modbus`/`modsan` 双列）→ 使用 modbus 列，
     modscan 列弃用；
   - **只有 modscan 编号** → 换算为 modbus 地址（编号 − 空间基值：10001 → 0、
     30001 → 0、40001 → 0……即减 1 后减空间基），换算须在方案中**明示**
     （「10001 → 离散输入 0」形态），禁止静默换算；
   - **判定特征**（存在即自动判定）：表头/列头含 modscan 字样、`4x/3x/0x/1x`
     前缀记法、功能码与编号域的组合特征（FC2 + 1xxxx、FC4 + 3xxxx）、同表
     双列比对、表内显式基址声明与序号序列自洽（高力板遥信标本：序号 0/1/2 三行的
     文字格「遥信起始地址：1/2/3」= 基 1 起的 modscan 编号，序号 0 行并列
     备注格「遥信起始地址：0」= modbus 0 基基址）；**无任何自证特征且无法
     排除歧义时必须追问确认**（宁可追问不可错绑——错一个基值全表地址
     错位）。
2. **类型辨识**：modbus 点表类型写法无规范（INT/int16/F32/DWORD/VT_R4/
   float/singed short…），解析时须辨识并映射到系统类型（ASFP2 枚举，§4.6.1），
   **并参考地址跨度交叉验证**：相邻点地址连续（差 1）→ 16 位（1 寄存器）；
   隔 1 个地址（差 2）→ 32 位（2 寄存器）；隔 3 个地址（差 4）→ 64 位
   （4 寄存器）。类型列缺失的表按跨度推导（16 位为推断结果时方案中明示
   「推断」）；类型列与跨度矛盾时以**跨度为准**并回报；拼写错误容错
   （`singed` → signed，不得因此拒收）。同义词映射基线：`INT/short/INT16/
   Int16` → INT16；`UINT/WORD/UINT16` → UINT16；`DINT/LONG/int32` → INT32；
   `DWORD/UINT32` → UINT32；`F32/float/REAL/浮点数/VT_R4` → FLOAT32；
   `F64/double/VT_R8` → FLOAT64；`bool/BOOL/布尔/VT_BOOL` → BOOLEAN（位空间）。
3. **字序（交换）**：多寄存器值存在字序/字节序差异，各表表述不一——`ABCD/
   CDAB/BADC/DCBA` 记法、「交换」「字间先低后高」等中文描述。映射基线
   （小端部署机，c4_modbus_client.md §4.6.2）：ABCD（高字在前，标准大端）→
   `hton_register=1, swap=2`；BADC（寄存器内字节交换）→ `hton_register=0,
   swap=2`；CDAB（低字在前，「字间先低后高」）→ `hton_register=1, swap=0`；
   DCBA（完全反转）→ `hton_register=0, swap=0`。16 位/位类型 swap 恒 0；
   表内有明确声明 → 解析落配置并在方案中**明示字序采纳**；表述含糊
   （仅「交换」二字）→ 追问澄清；无声明 → 按 ABCD（swap=2）缺省并在方案
   明示为缺省假定。
4. **控制组（写）不采集**：写寄存器/写线圈段（功能码 5/6/16），或表名/段名
   命中「遥控/遥调/控制/powercontrol/可写」**子串**（如「单机控制点数据」「遥调
   点」）→ excluded 回报不接入（与 IEC104 组遥控/遥调排除口径一致；表名
   匹配为子串语义，与 IEC104 组排除组匹配同款）。
5. **多设备展开三形态**：横向列组 + 偏移量声明（「每台机组地址偏移量500」）、
   AREA/群组声明（前缀+起始编号+数量+地址间隔）、地址计算公式（起始地址+
   (风机号−1)×块长+序号）→ 按声明展开为逐台点集；**台数无法从表内确定时
   追问**（表内「……」省略不算声明）。
6. **缩放/标定列不落 config**：modbus 采集**原值透传**，无缩放概念
   （c4_modbus_client point 无 scale 字段）——表内系数/标定列（`系数`/
   `VariableScale`/`因数`/`RAW_ZERO~ENG_FULL`）不写入 points，方案中明示
   「原值接入，未应用标定」，工程量换算属 calculatord 职责。
7. **必填不猜（modbus 版）**：ip、port（无默认值）、从站号 uid、功能码
   ——表内无依据（列/表头声明）时必须追问，禁止按 502/1/FC3 惯例自动填充
   （与主套件用例 31 同口径）；连接参数允许来自表内**表头注释**（如「设备
   地址：1 端口号：503」），提取采纳并在方案中回显。
8. **列裁剪原则（2026-10-11 用户裁定）**：modbus 点表列多而杂，C4 **只关注
   采集必要列**——点名（取值口径见规则 9：中文优先，机器标识列不作点名）、
   地址、
   数据长度/寄存器数量（跨度）、类型、功能码（含 `Holding_register/
   Input_register` 寄存器类型列 → fun 3/4 映射）、字序声明、设备语境；其余列
   （备注/系数/单位/标定/编码解释等）**不读、不因**——位打包说明（「状态点
   在该地址的前八位」）、地址 ±1 备注、故障/告警码枚举解码等**上层业务语义
   不进入采集配置**，也不因备注存在而追问/拒收/拒接入。**无地址列的 sheet
   是码表/说明页**（如「故障值/中文解释」「告警编码/中文解释」「状态值/中文」
   ——首列虽为纯数字但无地址语义）：不产点、不计入解析对账，方案中以说明
   形式带过即可。**多 sheet 文件的对账范围 = 断言指名的数据 sheet**：同内容
   人类可读副本（如京城 Sheet1 为遥测 sheet 的无表头副本、华创 sheet1 的
   「遥测点 功能码04」段与 Sheet3 同内容）、无表头原始导出块（如华创 Sheet2
   逗号串）不产点、不计入对账——照解析即撞键（POINT_DUP），属解析缺陷。
   **跨表同址同名合并裁定（2026-10-12 用户裁定，上海电气）**：同一物理点在
   多 sheet 重复表述（同 (fun,addr) 且点名相同）时合并为同点、**不计撞键**——
   上海电气四张数据 sheet 即此形态：主表「接入点表」3075 行 + 分表「遥测」
   1200 /「遥信点表」150 /「遥测发电量」75（三表与主表段 1/2/3 地址 100%
   重合、同名同址，分表头部 Variable 声明兼作主表功能码/类型补全来源）=
   **4500 行对账**；「遥控」分表与主表控制段同址同名、按控制组整组排除
   （组级回报一次，不重复计行）；同址**异名**不得静默合并——「故障」分表与
   主表段 5 同址但点名异构（「实时故障N」vs「ErrorN"」），不产点、不计对账
   （照解析即同址异名撞键）；故障解析为码表、白名单为 IP 备注页，不产点。
   合并裁定**适用边界**（2026-10-13 用户裁定）：同址同名副本是否合并，取决于
   副本是否承载主表缺失的权威信息——上海电气分表承载功能码/类型声明（合并
   计对账）；华创 `sheet1`「遥测点 功能码04」段 1930 行虽与主表 FC4 1929 行
   同址同名一致，但为纯人类可读视图、不承载新信息，不产点、不计对账
   （维持 Sheet3 1971 口径）。
9. **点名取值（2026-10-11 用户裁定）**：点名**一律优先中文名**；无中文名的
   行回退英文/机器标识名；两者均缺失才追问。同表并存多个人名列时（如
   「英文解释 + 中文解释」「edos id + 描述」）点名取中文列，机器标识列不作
   点名（可作方案展示信息）。点 id = **设备语境 + 点名** 两段合成
   （§3.2.1.3b 设备语境并入）——modbus 表通常设备与点名分列，表头措辞含糊时
   按值形态分析判定（离散分组重复列为设备列、逐行变化列为点名列），撞名
   判定以合成后 id 为准：跨设备同名合法，**同设备内同名即业务撞名**。无
   表头/单名单列表不适用本条多列选择逻辑。中文点名下的业务撞名**按三裁
   正常拒收，不因「中文优先」豁免**——表内中文重名属厂家维护错误，
   fail-visible 拒收正是应有行为。
