# e2e 模拟器使用手册（modbusd / iec104d / redis_tool / influxd）

> 2026-10-19 建档（用户指令：把 iec104d、modbusd 以及 redis_tool 的使用方法记录下来，
> 以便下次测试的时候使用）。e2e 环境资产放 `/tmp`，机器重启即失——按本文档重建约 5 分钟。

## 0. 总览

| 组件 | 角色 | 监听 | 配置 | 值来源 |
|------|------|------|------|--------|
| modbusd | modbus 从站（TCP 502x） | 5020 / 5021 | /tmp/c4_env/modbusd.json、/tmp/c4_env_52/modbusd_52.json | redis 文本值（with_timestamp=0） |
| iec104d | IEC-104 从站（受控站） | 2404 / 2405 / 2406 | /tmp/c4_env_104{A,B,C}/iec104d_24xx.json | redis 二进制值（with_timestamp=1，**必须 redis_tool -w 写入**） |
| redis_tool | 向 redis 写/读点值（采集族统一格式） | — | — | — |
| influxd 1.8 | 入库目标 | 127.0.0.1:18086 | /tmp/c4_influxdb/influxdb.conf | hnals 库 DROP+CREATE |
| asfp2 | 转发接收端由 e2e 框架自起（start_receiver），无需手工 | — | — | — |

通用约定：
- 所有守护进程需 `export ACQUISITION=/var/acquisition`。
- `engine.pwd` 指向各自工作目录；**`log.dir` 必须是 `"log"`**（其他值会导致守护进程退出）。
- redis：本机 6379，dbid 0，无密码。

## 1. modbusd（modbus 从站模拟）

配置要点（/tmp/c4_env/modbusd.json，5021 实例同构换 port/points）：

```json
{
    "engine": {"pwd": "/tmp/c4_env", "stop_check": 100},
    "log": {"dir": "log", "file": "log.log", "level": 1, "debug_time": 300, "size": 128},
    "modbus": {"ip": "0.0.0.0", "port": 5020, "hton_register": 1, "hton_total": 0,
               "swap": 2, "timer": 1000},
    "redis": {"ip": "127.0.0.1", "port": 6379, "dbid": 0, "auth": "",
              "with_timestamp": 0, "precision": 6},
    "points": [
        {"key": "SIM_MB_3000", "modbusaddr": 3000, "funcode": 2, "type": 10},
        {"key": "SIM_MB_3012", "modbusaddr": 3012, "funcode": 3, "type": 10}
    ]
}
```

- **funcode**（modbusd 侧语义，与线缆功能码不同）：0=线圈、1=离散输入、2=保持寄存器、
  3=输入寄存器。用例 30 的「功能码4 输入寄存器」= funcode 3。
- **type**：10=FLOAT32、15=BIT（用例 31 线圈 4000）。
- **swap=2**（与 agent 侧 c4_modbus_client 的 swap=2 匹配，值才 ABCD 正确）。
- **with_timestamp=0**：redis 里直接 `redis-cli MSET <key> <数值>` 文本即可（atof 路径）。
- 启动：`ACQUISITION=/var/acquisition nohup /usr/local/bin/modbusd -c <cfg> &`
- **log/ 目录必须预建**（工作目录下 `mkdir -p log`）——log_init 不自建目录，
  缺目录 = 静默退出 rc=255、无任何输出（2026-10-20 重建环境实测）

e2e 值口径（run_cases MB30_VALS/MB31_VALS）：

```
redis-cli MSET SIM_MB_3000 12.5 SIM_MB_3002 15.5 SIM_MB_3004 45.5 SIM_MB_3006 25.5 \
  SIM_MB_3008 220.5 SIM_MB_3010 28.5 SIM_MB_3012 30.5 SIM_MB_3014 30.0 \
  SIM_MB_3016 35.0 SIM_MB_3018 40.0 \
  SIM_MB2_4000 1 SIM_MB2_4100 41.5 SIM_MB2_4102 2.5 SIM_MB2_4104 60.0 \
  SIM_MB2_4106 3.2 SIM_MB2_4108 55.5 SIM_MB2_4110 0.8 SIM_MB2_4112 12.3
```

## 2. iec104d（IEC-104 受控站模拟）

三个实例：2404（公共地址 1，一号主变）、2405（公共地址 1，二号主变）、
2406（公共地址 2，三号主变，用例 37 异地址并存）。

配置要点（/tmp/c4_env_104A/iec104d_2404.json，B/C 同构）：

```json
{
    "engine": {"pwd": "/tmp/c4_env_104A", "stop_check": 100},
    "log": {"dir": "log", "file": "log.log", "level": 1, "debug_time": 300, "size": 128},
    "iec104": {"ip": "0.0.0.0", "port": 2404, "k": 12, "w": 8, "t0": 30, "t1": 15,
               "t2": 10, "t3": 20, "modules": 32768, "common_address": 1,
               "with_cp56time2a": 0, "acquisition_of_events_timer": 1000,
               "cyclic_data_transmission_timer": 0, "timer": 1000},
    "redis": {"ip": "127.0.0.1", "port": 6379, "dbid": 0, "auth": "",
              "with_timestamp": 1, "precision": 6},
    "points": [
        {"key": "SIM_104A_16385", "104addr": 16385},
        {"key": "SIM_104A_1", "104addr": 1},
        {"key": "SIM_104A_25601", "104addr": 25601}
    ]
}
```

- **地址分区定类型**：1~ 遥信（M_SP_NA）、16385~ 遥测 float（M_ME_NC）、25601~ 遥脉（M_IT_NA）。
- **with_timestamp=1**：redis 值必须是「float + 毫秒时间戳」二进制格式——
  **必须用 redis_tool -w 写入**（plain `redis-cli SET` 文本值会导致点无效：
  无突发数据、总召空，早期还触发 station MAKE_APDU「Invalid APDU Length」错误日志）。
- 值口径（run_cases T104_34/35_VALS 多重集覆盖）：16385 UAB=220.5、16386 UBC=50.2、
  16387 UAC=220.5、遥信1=1、遥信2=0、电度 25601=1024。
- 启动：`ACQUISITION=/var/acquisition nohup /usr/local/bin/iec104d -c <cfg> &`
- **重启禁令**：`pkill -f 'iec104d -c /tmp/...'` 会匹配到自己 shell 的命令行文本
  （自杀，两次实测）——用 **`pkill -x iec104d`**（精确进程名）或按 pid。
- 自发数据只在**值变化**时发：redis_tool 写值发生在 iec104d 启动前 = 初始值，
  无突发是正常行为；数据获取靠总召（产品客户端 c4_iec104_client 标准流程）。

## 3. redis_tool（采集族 redis 值写入器）

```
/usr/local/bin/redis_tool -s 127.0.0.1 -p 6379 -d 0 -F <点表文件> -t 1 -V <值> -w
```

- **`-w` 才是写模式**！不带 `-w` 默认是**读**（校验用），不带 -w 跑完只会打印
  「Read data from redis key」——第一次使用极易踩坑。
- `-F` 点表文件：一行一个 redis key（与守护进程配置 points[].key 一致）。
- `-V` 单值：一次运行给文件里全部 key 写同一个值——不同值分多个文件多次跑。
- **`-n` = 不带时间戳**（配守护进程 `with_timestamp: 0`）；默认带毫秒时间戳
  （配 `with_timestamp: 1`，iec104d 样例即此）。**两边必须匹配**。
- `-t 1` 跑一次即退；`-r` 随机 float32-exact 值（压测用）。

iec104d 三实例的值写入实例（/tmp/c4_env_104rt/）：

```
v220.txt:  SIM_104A_16385 / SIM_104A_16387 / SIM_104B_16385 / SIM_104C_16385   → -V 220.5
v50.txt:   SIM_104A_16386 / SIM_104B_16386 / SIM_104C_16386                    → -V 50.2
v1.txt:    SIM_104A_1 / SIM_104B_1 / SIM_104C_1                                → -V 1
v0.txt:    SIM_104A_2                                                          → -V 0
v1024.txt: SIM_104A_25601 / SIM_104B_25601 / SIM_104C_25601                    → -V 1024
```

## 4. influxd 1.8（入库目标）

- 配置 /tmp/c4_influxdb/influxdb.conf（meta/data/wal 目录 + http 127.0.0.1:18086）。
- 启动：`nohup /home/wangbo/backup/influxdb/influxdb-1.8.10-1/usr/bin/influxd \
  -config /tmp/c4_influxdb/influxdb.conf &`
- hnals 库清理（shard 字段类型锁，用例 38 前必做）：
  `curl -X POST 'http://127.0.0.1:18086/query' --data-urlencode 'q=DROP DATABASE hnals'`
  再 CREATE。（run_cases 的 case_reset/start_influxd 已内置。）

## 6. 已知鲁棒性问题（回归时注意，勿手工造帧打这些端口）

- **libiec104（受控站侧）对短帧/残帧走 assert 中止**（data_unit.c:101
  `decode_length == APDU_HEADER_LENGTH + apdu_length`）而非优雅丢弃——畸形帧会打死
  iec104d。建议基础设施组改为计错丢帧。
- iec104d 对乱序/越序 I 帧的处理亦会崩溃（2026-10-19 实测两次）。
- e2e 正常流程（产品客户端 ↔ 产品从站）不触发以上两条。
