## 失败用例诊断（7 项）

### ① 13B——未知协议未 fail-fast（模型纪律）
输入「使用abc协议」，agent 未回显未知协议名、未列已部署协议清单，直接输出 `### 接入方案`。用例 13 设计：未知协议 → 可读错误 + 协议清单；改声明 asfp2 后才接入。GLM 此前通过。

### ② 77——坏 key 422 场景失效（**测试基建缺口，非产品 bug**）
`agent_start(bad_key=True)` 只污染 `ZHIPU_API_KEY`（run_chain_site_change.py:118）；Deepseek 开关下模型读 `DEEPSEEK_API_KEY` 仍有效 → LLM 正常生成缩写 `gd` → 200 ≠ 期望 422。68~76 全过。修复方向：bad_key 时按 provider 同步污染对应 api_key_env。

### ③ D1-38——influx 点 type 未落库（模型推导缺失）
用户明说「类型统一float」，落库点 `type=None`。v2.1.76 起 type 为 optional（不再被门禁强制），Deepseek-chat 不主动携带 optional 字段；registry 的 type 推导提示未起作用。GLM 此前通过（今早 sweep 同消息 38 也是 PASS，但该断言只查字段对点，未查 type——influx 链 D1 的 s38 断言更严）。

### ④⑤ RP-IF-01/02——CSV influx 映射整体未携带（模型推导缺失，同 ③）
AZGF CSV 第 4 列 jd（measurement）、field/tags/type 列全部未映射进方案：写入标签列退化为纯地址数字（`| 1009 | … | 1009 |`），落库 type=None ≠ 期望 bool/float。设备名同样绑成整句（见 ⑥ 同款）。1212 点大表 + 每点 4 项映射，非思考模型未执行。GLM 在 10-14 全过。

### ⑥ MB-01——设备裸名绑定失败（模型纪律）
用户答「设备名叫海林华锐，就用这些点表」，agent 将**整句**绑为设备名（确认列表可见 `设备：设备名叫海林华锐，就用这些点表`），随后循环追问，未到确认按钮。用例 47 的裸值绑定规则（47A~D 本轮全过）未覆盖「名叫X，就用……」长句形态。GLM 10-14 通过。

### ⑦ MB-10——1971 对账不可见（**既有产品缺口，非模型问题**）
对账口径输出 3926 行（含 Sheet1 纯视图副本并入），违反 2026-10-13 裁定「Sheet1 副本不计对账、维持 Sheet3 1971」。与 10-14 GLM 全量跑的失败完全同签名——v2.1.73 的裁定当时仅离线探针验证，e2e 一直未过。
